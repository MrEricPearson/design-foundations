# Data Visualization for Decision-Makers
**Tier:** 200 — Practice | **Arc:** Standalone | **Prereqs:** None

**Goal:** After this piece, you will be able to choose a chart type based on the decision it needs to support, not on what looks impressive.

**Prior knowledge hook:** Think of a chart you've seen in a meeting that looked impressive — but when someone asked "so what should we do?" nobody could answer from the chart alone.

**Trigger:** you're building a chart or dashboard meant to inform a real decision.

**Why this works:** a chart that can't support a decision isn't a visualization — it's decoration. Starting from the decision defines which data matters and what form makes it legible, rather than starting from data and hoping a useful visual emerges.

**Method:** before choosing a chart type, ask what decision this needs to support — then pick the simplest visual that answers that question honestly, not the one that looks most impressive.

**Artifact:** one chart chosen for clarity, not impressiveness.

**Watchout:** a persuasive chart isn't the same as an accurate one — don't design to win the argument.

**Try This:** find a chart you're currently working on or recently built. Write one sentence: "This chart helps someone decide ___." If you can't finish it, the chart doesn't have a clear purpose yet — go back to the decision before choosing the visual.

**Proof:** State the decision the chart is meant to support, then ask whether someone who hasn't seen your analysis could make that decision from the chart alone. If yes, it's clear. If no, it's either the wrong chart type or carrying too much information for the decision it's meant to serve.

**Take this further:** in the next week, share the chart with the person who needs to make the decision it's meant to support. Write one sentence: did they make the decision from the chart, or did they need you to explain it? Explanation means the chart isn't done.

**After you've run this yourself:** describe the data and the decision it needs to support to an AI tool and ask which chart type best serves that decision — then check whether its recommendation actually makes the decision easier to reach before using it.

**What Next:** if the chart is part of a larger dashboard meant to track ongoing outcomes, pair it with 217 (UX Metrics) to connect the visual to measurable targets. If you're designing data-heavy interfaces and need to control information load, read 119 (Progressive Disclosure).
