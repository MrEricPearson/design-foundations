# Retrospective for Design Decisions
**Tier:** 200 — Practice | **Arc:** Standalone | **Prereqs:** 209 (decision records), 113 (defining success) | **Note:** Feeds 305 (Did-It-Work Follow-Up)

**Goal:** After this piece, you will be able to run a short, honest review of a past decision and produce a one-paragraph record of what held up and what didn't.

**Prior knowledge hook:** Think of a decision from a past project that turned out differently than expected — where the stated reason for it now seems either obviously right or obviously wrong in hindsight, but nobody went back to say so officially.

**Trigger:** some time has passed since a decision was made, and it's worth checking whether it actually held up.

**Why this works:** memory rewrites reasoning over time — what you remember as the rationale for a decision tends to converge with the outcome. Revisiting the original record before that convergence is complete is the only way to get honest signal about whether the reasoning was actually sound.

**Method:** revisit the Design Decision Record (or your stated success definition) and ask honestly — did this work the way we expected? What would we do differently?

**Artifact:** a short, honest after-the-fact note on one past decision.

**Watchout:** this only works if honesty is safe — if looking back always turns into blame, people will stop doing it.

**Try This:** find one decision from the last month that had a stated success condition. Write three sentences: what the condition was, whether it was met, and what you'd do differently. That's a retrospective.

**Proof:** "Did this work the way we expected?" has three possible honest answers: yes, no, or can't tell. All three are more useful than not asking. The one outcome this method doesn't produce is the false certainty that comes from never checking.

**Take this further:** in the next two weeks, run this check on one more past decision. Write one sentence: is there a pattern in which types of decisions consistently don't hold up the way you expected?

**After you've run this yourself:** paste the original decision record (or your best memory of it) and the actual outcome into an AI tool and ask it to identify the gap between expected and actual — then write your own sentence on what you'd change; the AI output is a starting prompt, not a conclusion.

**What Next:** if this pattern surfaces repeated problems with a specific type of decision, read 305 (Did-It-Work Follow-Up) for a more structured post-launch review. If decisions are getting revisited without this record to anchor them, read 209 (Decision Records) to start writing them at the time.
