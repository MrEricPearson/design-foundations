# Content Design / UX Writing
**Tier:** 200 — Practice | **Arc:** Standalone | **Prereqs:** 303 Pt 1 (Vocabulary Checks); pairs with 116 (error states), 117 (empty states), 133 (visual hierarchy)

**Goal:** After this piece, you will be able to rewrite any interface copy into language a user can act on — without the jargon or the passive voice.

**Prior knowledge hook:** Think of a label or button you've seen that made you pause — not because it was wrong, but because you had to translate it before you knew what would happen. That translation cost is what interface copy is responsible for.

**Trigger:** you're about to write a label, message, or instruction and default to whatever sounds official.

**Why this works:** interface copy that sounds official often prioritizes how the system thinks about itself over what the user needs to do next. The out-loud test breaks the "official" reflex — if you wouldn't say it to a colleague, it's not serving the user; it's serving the system's self-presentation.

**Method:** write it the way you'd say it out loud to a colleague, then trim anything that doesn't help someone take their next action.

**Artifact:** one piece of interface copy, rewritten in plain, direct language.

**Watchout:** casual doesn't mean vague — "friendly" tone still needs to be precise about what's actually happening.

**Try This:** find one button label, section header, or error message in something you're building. Read it out loud. If it sounds different from how you'd say it to a colleague, rewrite it until it doesn't.

**Proof:** Read the rewritten copy out loud. If it sounds like how you'd actually say it to a colleague, it's working. If it sounds like it was written to sound official, something official crept back in.

**Take this further:** in the next few days, pick three copy items across a product you work with and apply the out-loud test. Write one sentence: which type of copy tends to fail most consistently (labels, error messages, instructions)?

**After you've run this yourself:** paste existing interface copy into an AI tool and ask it to rewrite each item in plain, direct language — then check each for precision (does it still say exactly what the original meant?).

**What Next:** if the content involves states that don't exist yet (errors, empty screens), apply this method to those as well in 116 (Error States) and 117 (Empty States). If you're auditing terminology consistency across the product, start with 303 Pt 1 (Vocabulary Checks).
