# Default as a Design Decision
**Tier:** 100 — Recognize | **Note:** Soft prereq for 307 (Dark Pattern Awareness); pairs with 307

**Goal:** Recognize that defaults are design decisions — not neutral starting points — so you can evaluate what the default is actually optimizing for.

**Concept:** A default is the state a system starts in when the user hasn't made an explicit choice. Defaults appear neutral because they require no action, but every default encodes a choice about whose interests to serve first: the user's, the product's, the organization's, or someone else's. A form pre-filled with opt-in to marketing is a default that optimizes for subscription numbers. A privacy setting defaulted to "share with partners" is a default that optimizes for data. The design question is not "what should the default be?" — it's "what is this default for?"

**You'll see it when:** A setting, form field, permission, or checkbox is pre-selected without any explicit user action. The pre-selection is always a design decision, even when it was never consciously made — a default left at the system's initialization value is still a choice to leave it there.

**The signal:** Ask "who benefits from this default?" If the answer is primarily the user — it saves them effort in the most common case and makes the most desirable outcome the path of least resistance — the default is working for the user. If the answer is primarily the product or organization — it captures a consent, a subscription, or a data sharing permission the user might not choose actively — the default is working against the user.

**Don't confuse this with:** All product-benefiting defaults being dark patterns. A default that serves the product can also genuinely serve the user — it depends on whether the user would choose it if they were paying attention. The dark pattern version is when the default captures something the user wouldn't choose if they noticed it.

**Try Noticing:** Find one default in a product you're working on or using — a form field, a setting, a permission. Ask: does this default make the most common or most desirable user choice automatic? Or does it make the product's preferred outcome the path of least resistance? That question is the design decision.
