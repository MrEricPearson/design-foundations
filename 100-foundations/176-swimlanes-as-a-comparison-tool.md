# Swimlanes as a Comparison Tool
**Tier:** 100 — Recognize | **Note:** Foundational prereq for enterprise-scale journey mapping (206 arc); pairs with 175 (What a Journey Map Is)

**Goal:** Recognize when a journey map needs swimlanes and what question they make it possible to answer.

**Concept:** A swimlane is a horizontal track in a journey map that follows a distinct persona or role through the same overall journey. When a single journey involves more than one type of person, each gets their own lane — so you can see, side by side, where their experiences align and where they diverge. Without swimlanes, a multi-persona experience either gets flattened into one generic path that's accurate for no one, or gets mapped separately in ways that can't be compared.

**You'll see it when:** You're mapping a process that more than one type of person goes through — and the steps, touchpoints, or frustrations are meaningfully different depending on who's doing it. The question stops being "what does this person experience?" and becomes "where do these people's experiences converge, and where do they split?"

**The signal:** You've added a second persona to your thinking and realized you can't fit their steps into the same row without losing important differences. When "same steps, different experience" stops being accurate — when the steps themselves differ between roles — swimlanes are the right move.

**Don't confuse this with:** The frontstage/backstage structure of a service blueprint, which separates what users see from what happens behind the scenes — that's a visibility distinction, not a role distinction. Swimlanes in a journey map separate different user roles from each other; they don't separate visibility layers.

**Try Noticing:** Think of a process you're working on. Ask: is there more than one type of person going through this, and do their steps actually differ — or just their feelings about the same steps? If the steps themselves differ, a multi-lane map captures that. If only the sentiment differs, the difference can live in annotations on a single lane.

**What Next:** If you're building a journey map that needs swimlanes, you're working at the enterprise-scale version described in the 206 journey mapping arc. Start with the approach that fits your access level, then add lanes once the primary persona's path is mapped — one lane at a time, same scope, so the comparison stays readable.
