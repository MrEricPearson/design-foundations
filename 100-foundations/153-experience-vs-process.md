# Experience vs. Process
**Tier:** 100 — Recognize | **Note:** Foundational prereq for all journey mapping pieces (206c, 206a, 206b); pairs with 154 (What a Pain Point Is)

**Goal:** Recognize the difference between a user's experience and a process — so you know which one you're mapping.

**Concept:** A process describes how a system or workflow is designed to operate — the intended sequence of steps. An experience describes how a person moves through reality — what they actually do, think, and feel as they try to accomplish a goal. A process can be well-designed and still produce a poor experience, because processes are built around system logic, and users don't read system logic before attempting a task.

**You'll see it when:** A team describes "the user flow" by reciting the intended system sequence — what the product is supposed to do — rather than what users actually do when they encounter it. The map they're building describes the process; the experience lives in the gap between that process and what users actually encounter.

**The signal:** If the steps describe what a system does, it's a process. If the steps describe what a person does — including the detours, moments of confusion, workarounds, and unexpected paths — it's an experience. The presence of workarounds and detours in a description is the strongest signal that it's describing experience rather than process.

**Don't confuse this with:** A user flow or interaction flow in a design tool, which describes the intended interaction path — the process you're designing toward. Those are useful for building; a journey map is useful for understanding what currently exists before you design anything.

**Try Noticing:** Look at the last process diagram or user flow you worked with. Would any of the steps change if you were describing what users actually do rather than what the product was designed to do? That delta — the gap between the intended path and the real one — is the experience.

**What Next:** When you're ready to map a current-state experience, start with the journey mapping arc (206-journey-mapping-arc.md). When you're designing the intended future-state interaction, a user flow is the right tool — the experience you're building toward, not the experience that currently exists.
