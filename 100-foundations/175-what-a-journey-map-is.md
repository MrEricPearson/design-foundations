# What a Journey Map Is
**Tier:** 100 — Recognize | **Note:** Foundational prereq for 206c, 206a, 206b (all journey mapping approaches); pairs with 176 (Swimlanes)

**Goal:** Recognize what a journey map is, what problem it solves, and what makes it different from other diagrams that also describe a process.

**Concept:** A journey map is a visual record of the steps someone goes through to accomplish a goal — from their perspective, not the system's — with attention to where the experience works and where it breaks down. It makes visible the gap between how a process looks from the inside and how it feels from the outside.

**You'll see it when:** A team is describing "how the user does X" and each person on the team has a slightly different picture of what that looks like — which steps are involved, what the user is trying to do at each one, and where it gets frustrating. The conversation keeps circling because there's no shared reference. A journey map is the document that ends that kind of conversation.

**The signal:** A journey map has three things: a persona or role (whose journey this is), a sequence of steps (what they actually do, in order), and some indication of where the experience fails — friction, confusion, drop-off, or workarounds. If any of the three is missing, what you're looking at is probably something else.

**Don't confuse this with:** A process map or flowchart, which documents how a system or workflow is designed to operate — not how a person experiences it. A process map answers "what are the steps?" A journey map answers "what is it like to go through those steps?"

**Try Noticing:** Think of something you're currently working on that involves a person trying to accomplish something. Is there a documented sequence of steps from that person's perspective — not from your team's process, but from their experience? If that document doesn't exist, the gap between your team's mental model of "how the user does this" and the user's actual experience is currently invisible.

**What Next:** If you're ready to build one, start with the approach that matches your access — if you have no observations or research yet, start with 206c (Assumption-First Proto-Map). If you have research or observations to draw from, use 206a (Discovery-Driven Journey Map). If you need a group to build one together, use 206b (Co-Creative Journey Map). If you want to map the systems behind a journey map you've already built, read 306 (Service Blueprint).
