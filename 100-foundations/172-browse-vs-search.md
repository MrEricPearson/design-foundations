# Browse vs. Search
**Tier:** 100 — Recognize | **Note:** Soft prereq for 204 (Information Architecture) and 218 (Card Sorting); pairs with 204 and 218

**Goal:** Recognize when users are browsing versus searching — and what each mode requires from the product.

**Concept:** Browsing is exploratory — the user doesn't have a specific target, they're scanning to find something they'll recognize when they see it. Searching is purposive — the user has a specific target, they know what they're looking for, and they need the fastest path to it. Both modes appear in the same product and often in the same session. The design failure is building a navigation that serves one mode well and ignores the other.

**You'll see it when:** Users in browse mode try to use search and get frustrated because they don't know the right search term for what they're looking for. Or users in search mode try to browse and get frustrated because the navigation structure requires them to know where the product thinks the content lives. Both failures are navigation failures — but they're different navigation failures.

**The signal:** In browse mode, users are scanning menus, clicking on category labels to see what's inside, and backing up frequently. In search mode, users go directly to the search bar, try keyword variations, and don't engage with the navigation structure. Both behaviors are visible in analytics (search usage patterns) and in usability sessions (where users go first when looking for something).

**Don't confuse this with:** The difference between good and bad navigation. Some products legitimately serve primarily search-mode users (specialized tools where users know exactly what they need) and others serve primarily browse-mode users (discovery-oriented platforms). Both can be well-designed. The problem is when the navigation doesn't support the mode the actual users are in.

**Try Noticing:** For a product you're working on, watch how someone tries to find something they haven't found before. Do they go to the search bar or to the navigation? If most people go straight to search, they're behaving like they're in a primarily search-mode product — and the browse navigation may not be supporting the use case it was designed for.

**What Next:** When designing navigation structure that needs to support browse behavior, read 204a (Task-Based IA) or 204b (Content-Based IA). When validating whether users' browse mental models match your navigation structure, read 218 (Card Sorting).
