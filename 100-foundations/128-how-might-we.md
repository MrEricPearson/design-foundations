# How Might We Questions
**Tier:** 100 — Recognize (Practice Atom) | **Arc:** Standalone | **Prereqs:** 107 | **Episode:** 2

**Goal:** Recognize when a problem statement is being used to generate a single obvious solution rather than open a design space — and convert it into a question that preserves optionality.

**Concept:** The working assumption is that a clear problem statement leads naturally to a solution — that once you've named the problem, the appropriate response becomes evident. The correction: a problem statement names what's wrong; it doesn't control how many possible responses exist. When a problem statement is stated in a way that's already oriented toward a specific solution, it closes the design space before exploration happens. The mechanism: "How Might We?" works because the three words each do specific work. "How" assumes a solution exists — the question is solvable. "Might" preserves possibility — not prescriptive or evaluative, but exploratory. "We" establishes collective ownership — the response isn't assigned to a person or role. A problem statement converted to a HMW question at the right scope produces multiple plausibly valid responses that are different from each other. That divergence is the signal that the design space was opened rather than closed.

Scope matters: too narrow collapses back to a single obvious response; too broad loses connection to the real problem. The right scope: specific enough to point at the actual problem, open enough that three genuinely different solutions could answer it.

**The move:** Take a problem statement and write three HMW versions — one too narrow (already a solution), one too broad (any response is valid), one at the right scope. Use the middle version as the brief for ideation.

**Don't confuse a HMW question with a problem statement.** A problem statement names what's wrong. A HMW question opens the space of what might address it. You need the problem first — HMW is a reframe, not a replacement. A false positive: "How might we improve the search experience?" feels like an open question and is too broad — almost any change to search could be a valid response. The right scope requires knowing what specifically is failing about search and opening responses to that, not to search in general.

**Try Noticing:** Take the last problem statement from your current work. Write a HMW version of it. Now ask: could someone write three genuinely different solutions to this question? If all three converge on the same response, the scope is too narrow. If none of them connect to the real problem, the scope is too broad.

**What Next:** Take the HMW question to 203 (Structured Ideation / Crazy 8s) to generate multiple directions before evaluating. If the HMW question revealed that the problem itself isn't yet well-framed, return to 107 (Framing the Problem).
