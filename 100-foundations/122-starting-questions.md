# Starting Questions
**Tier:** 100 — Recognize (Practice Atom) | **Arc:** Standalone | **Prereqs:** 107, 113 | **Episode:** 2

**Goal:** Recognize the five types of unexamined assumptions that reliably cause problems later — and surface them before work begins rather than after.

**Concept:** The working assumption is that thinking clearly about a problem before starting it produces overhead — you can figure out what you're solving as you build. The correction: the five assumptions that most reliably derail work in progress are almost always answerable before the work starts, and almost never get examined once it's underway. The mechanism: work in progress generates momentum and investment. Questions that could have been asked in five minutes at the start take exponentially more to resolve once work has built on unexamined answers. The assumptions that go unexamined aren't the hard ones — they're the ones where nobody thought to ask.

The five:
1. **The problem**: *[Who] is struggling to [do what], because [why].* If any blank stops you, you don't have a problem statement yet.
2. **The definition of success**: *I'll know this worked if ___.* Answerable before the result exists; the only version that can be wrong.
3. **The alternatives**: Is this the only path forward? Name one other option before committing to direction.
4. **The hidden options**: If this were guaranteed to succeed, what would you do that you're currently holding back? This surfaces choices being avoided for the wrong reason.
5. **The shared definition of done**: What does everyone involved think "done" means? Where answers differ, close that gap first.

**The move:** Before starting any piece of work, write all five answers down in a place that will be visible when the work is done. Answers that take longer than two minutes to write are findings — they name where the work actually starts.

**Don't confuse these questions with project planning.** Planning produces a plan. These questions surface whether the plan has a foundation. A false positive: a detailed project plan that answers what, when, and who — but where question 2 ("I'll know this worked if ___") produces a feeling rather than an observable outcome. The plan exists; the basis for evaluating it doesn't.

**Try Noticing:** Look at the last piece of work you started. Can you answer all five questions for it now? Notice which ones were never explicitly answered — and whether anything that went wrong tracks to one of those gaps.

**What Next:** If question 1 stops you, read 107 (Framing the Problem). If question 2 stops you, read 113 (Defining Success). If question 3 surfaces a direction worth weighing, read 109 (Weighing Trade-offs).
