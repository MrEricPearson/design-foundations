Quality Benchmarks

A comprehensive evaluation rubric for every piece in the library — T100, T200, and T300. All BLOCKING benchmarks must pass before publication. Advisory benchmarks should reach ≥ 85%. Benchmarks marked NEW extend the existing spec with criteria not previously formalized.

Blocking Must pass — publication is blocked until resolved
Advisory Should pass — judgment call; document the reason if skipped
New Not in existing CLAUDE.md spec — added from research or gap analysis
Research Grounding
Bloom's Taxonomy

T100 = Remember/Understand. T200 = Apply. T300 = Analyze/Evaluate/Create. Goal verb and cognitive demand must match tier — a piece that requires judgment at T100 or only recognition at T200 is misfiled.

Merrill's First Principles

Effective instruction activates prior knowledge, demonstrates the concept, provides application, and integrates with real work. All four should be present in every T200/T300 piece.

Sweller's Cognitive Load

Intrinsic load (concept complexity) is irreducible. Extraneous load (unclear structure, labeled templates, noise) is avoidable. Germane load (schema formation) is what the piece is for.

Keller's ARCS Model

Learning requires Attention (opens in the moment), Relevance (reader sees themselves in the Trigger), Confidence (Try This is achievable), and Satisfaction (Proof closes the loop). Weak ARCS = reader doesn't return.

Ericsson's Deliberate Practice

The Try This → Take This Further spaced arc is grounded here. Reflection prompts must require conscious self-correction — not just repetition. Learning type determines the right prompt.

Paivio's Dual Coding

Visual + verbal encoding is more durable than verbal alone. The image spec in the publish doc isn't cosmetic — it's the second encoding channel. Images that decorate rather than illustrate waste this.

Dimension 1

Learning Outcome Validity

Does the piece teach exactly what it claims? The goal statement is a contract with the reader. These benchmarks test whether the piece delivers on it.

Blocking
Blocking

Goal verb matches tier. T100: notice / identify / name / recognize / spot. T200: run / produce / apply / write / map / conduct. T300: decide / adapt / judge / orchestrate / navigate. A mismatched verb signals a misfiled piece.

A T100 that says "run a test" or a T200 that says "recognize when" is wrong tier. Reclassify before continuing evaluation.

Blocking

The stated goal is achievable in one reading session. Someone who finishes this piece can attempt the goal today with no additional instruction.

Blocking

One thing only. The piece teaches exactly one goal. Any passage that serves a different goal is either cut or broken into a separate piece.New

Apply the recursive decomposition test: if the piece could be explained as two distinct things, split it. Three or more sequential steps with a shareable artifact at T100 = re-tier to T200.

Blocking

Bloom's alignment holds. T100 targets Remember/Understand (the reader can name and recognize). T200 targets Apply (the reader can execute). T300 targets Analyze/Evaluate/Create (the reader can make judgment calls).New

A T100 that asks the reader to make judgment calls about context, or a T200 that only asks for recognition, fails this benchmark regardless of goal verb.

Advisory
Advisory

Novelty check: a PM, custom dev, or non-custom dev reading this would encounter something they couldn't derive from common sense or a Google search.New

If the piece's core claim is "here's something obvious with a design label on it," it will be dismissed. The mechanism or the framing must be genuinely new to the audience.

Advisory

Merrill's coverage: the piece activates prior knowledge (Prior Knowledge Hook or opening), demonstrates the concept in action (Concept/Method), gives the reader an application opportunity (Try This), and integrates with their existing work (Take This Further).New

Advisory

Transfer validity: the method or concept works in SaaS, 3rd-party, or non-custom-dev contexts where the reader doesn't have design authority over the interface.New

A method that only works when you control the codebase fails this audience. If the method is genuinely constrained to greenfield, that constraint must be named in the Trigger.

Dimension 2

Structural Completeness

Every tier template is a sequence, not a checklist. Element presence matters. Element order matters. Template labels visible to readers fail this dimension entirely.

All tiers — Blocking
Blocking

All required elements are present for the piece's tier. No element is absent or merged with another.

Blocking

Elements appear in prescribed order. Proof follows Try This — a Proof that precedes Try This functions as a preview, not feedback, and breaks the deliberate-practice arc.

Blocking

No template section labels are visible as reader-facing headers. Bold labels like **Concept:** or **Signal:** are author checklists — they do not appear in published prose. Structure is carried by --- breaks and narrative transitions.

T100 element sequence — Blocking
Blocking

Sequence present: Goal → Concept (1–2 sentences: what this is + why it matters) → You'll See It When → The Signal (one checkable sign) → Don't Confuse This With (adjacent concept + how to tell them apart) → Try Noticing → What Next.

Blocking

Don't Confuse This With names the one adjacent concept most often conflated with this one — not a generic disclaimer, not a list of similar things.New

The distinction must be sharp enough that after reading it, the reader could correctly sort three real examples into the right category. If it's fuzzy, tighten the distinguishing criterion.

T200 element sequence — Blocking
Blocking

Sequence present: Goal → Prior Knowledge Hook (1 sentence activating existing schema) → Trigger → Concept (the mechanism — why this method works) → Method (exact steps) → Artifact → Watchout → Try This → Proof → Take This Further → AI path → What Next.

Blocking

Concept names the mechanism — the reason the method works — not just a description of what the method does.New

"This works because…" should be answerable from the Concept section. If the Concept only describes the method's steps from a higher altitude, it hasn't explained the mechanism.

Blocking

Prior Knowledge Hook activates a schema this audience actually has — not assumed domain knowledge, not assumed familiarity with design process.New

A hook that assumes the reader has run a usability study before will miss the audience. The schema must be something a PM or developer would recognize from their own work.

Blocking

Method steps are minimal and sufficient. No step is a meta-instruction ("think about X," "consider Y"). Each step names one concrete action.

T300 element sequence — Blocking
Blocking

Arc header present: Goal (judgment verb) + Arc trigger (when this whole system applies). Per-part format present for each part: heading → Concept → Method → What you end up with → Proof → Watchout. Arc footer present: Try This + Take This Further + Judgment Exercise + What Next.

Blocking

Judgment Exercise names: (a) the arc's key assumption, (b) the specific situation where that assumption fails, (c) a question about that failure that couldn't apply to any other arc.New

Test: swap the Judgment Exercise into a different arc. If it still makes sense, it isn't arc-specific enough. The scenario must be the one failure mode that is uniquely dangerous for this arc's approach.

Advisory
Advisory

T100 Practice Atom subtype applied correctly: only when the doing IS the concept and there is at most one step. If ≥ 3 steps with a shareable artifact, re-tier to T200.

Advisory

T300 arc parts form a genuine Bloom's progression: Recognition → Differentiation → Application → Judgment → Synthesis. Each part adds a cognitive layer the previous part couldn't.

Dimension 3

Voice & Register

The wall rule: the discipline is invisible. The author is a peer sharing something useful — not a function making a case. Every sentence is either useful to the reader or absent.

Blocking
Blocking

No banned words. Full list: delve, tapestry, testament, illuminate, paradigm, intricate, multifaceted, nuanced, juxtapose, endeavor, quintessential, burgeoning, ubiquitous, synergistic, pivotal, paramount, navigate (metaphorical), embark, realm, landscape, nestled, leverage, facilitate, optimize, catalyze, holistic, robust, seamless, foster, comprehensive.

Also avoid: crucial, notable, significant, innovative, transformative, impactful, actionable, scalable, actually, certainly, essentially, ultimately.

Blocking

No banned openers: "Let's dive in" / "Let's explore" / "It's important to note" / "It's worth mentioning" / "At its core" / "In essence" / "Fundamentally" / "Generally speaking" / "In many cases."

Blocking

No banned closers: "In conclusion," / "To summarize," / "And that's why this matters." No rhetorical Q+A ("What does this mean? It means…"). No parallel negation ("Not X, but Y" — state the Y directly).

Blocking

The discipline is invisible. No sentence argues FOR design or positions design as a function. Every claim is argued from the reader's interest: better work, less rework, lower risk.

Blocking

No sentence implies the reader is currently doing something wrong. The author is a peer who figured something out — not a function flagging a deficiency.

Rewrite any sentence that, if said aloud, would make a colleague defensive. The same information can be framed as "here's what I found" instead of "here's what teams get wrong."

Blocking

Opens in the moment — no warmup paragraph, no announcement of what the piece will cover, no scene-setting preamble. The first sentence drops the reader into the highest-stakes observation.

Blocking

Second person throughout: "you," not "teams," "practitioners," "organizations," or "designers." The reader should feel addressed individually.

Blocking

Goal line and subtitle name the experience, not the concept.New

Test: does the subtitle make the reader think "yes, that's me" or "okay, so this is about X"? If it describes the concept instead of naming a felt moment, rewrite it. The concept is what the piece teaches. The subtitle is what makes someone decide to read it.

Advisory
Advisory

At least one moment of warmth, self-awareness, or levity per piece: a parenthetical aside, a small admission, a moment that acknowledges the reader as a person rather than a practitioner role.

The more the reader likes the author, the more they trust the content. Personality is a feature, not a distraction.

Advisory

One genuine moment of humor — not a pun, not a labeled joke, not a setup-and-payoff. Something true and recognizable that earns a smile, unless the subject is too serious.

Advisory

Contractions used throughout. "Don't" not "do not." "You're" not "you are." Formality signals distance; contractions signal a conversation.

Dimension 4

Sentence-Level Craft

Word count target is ~1,000 words. Under 700 is compressed, not crafted — personality requires room to breathe. These benchmarks are per-sentence and per-paragraph audits that require reading the piece, not skimming it.

Blocking
Blocking

At least one sentence of 6 words or fewer per 150-word block. Scan the entire piece in blocks. Short sentences are mandatory rhythm devices — the piece cannot achieve momentum without them.

Blocking

No three consecutive sentences within 5 words of each other in length. Consecutive same-length sentences flatten the rhythm and make prose feel machine-generated.

Blocking

Em dash inventory: no more than one per 300 words in body prose. No two em dashes in the same sentence. No two em dashes in adjacent paragraphs.

Em dashes inside quoted dialogue strings (as dialogue punctuation) are exempt from the body-prose count.

Blocking

Semicolons: near-zero. Replace with a period in nearly every case. A semicolon in prose signals a sentence that should be two sentences.

Blocking

Bold: maximum two instances per piece. Each instance must be genuine emphasis — a term the reader might miss that changes interpretation if they do. Not stylistic, not structural.

Blocking

Bullet soup rule: three or more bullets with identical openers convert to prose. The pattern "You can…/ You can…/ You can…" is bullet soup. Structural bullets listing distinct items are permitted.

Blocking

One idea per sentence. The "and" test: if a sentence carries two independent ideas connected by "and," split it into two sentences.

Blocking

Dead verb kill list. Replace every instance of: serves as, allows for, helps to, enables (in verb position), supports, facilitates, functions as. Replace with the thing they point at.

Target verbs that do things: breaks, reveals, forces, earns, kills, costs, surfaces, catches, names. Cut modifiers instead of strengthening them: very / quite / highly / extremely / somewhat → find a stronger word or cut.

Blocking

Cut test applied. For each sentence: remove it. Does the piece lose something that can't be recovered from context? If no — cut it. Restatements of the previous sentence are cuts. Transitions with no new content are cuts.New

Dangling analysis ("…highlighting the importance of…") always fails the cut test. The analysis should have been in the sentence it follows, or it's not needed.

Advisory
Advisory

Read-aloud test passes: a narrator reads every sentence without stumbling. Stumbles locate syntax problems, rhythm violations, or sentences that are doing too much.

Advisory

Piece identity: the opening paragraph is distinctive enough that you'd know which piece this is if you encountered it without its title.New

Strong pieces open with the most characteristic thing about their concept — a specific failure mode, a specific paradox, a specific moment. Generic openings ("Prototypes answer questions") could belong to any piece in the library.

Dimension 5

Action Section Quality

The action sections — Try This, Proof, Take This Further, AI path — are where the piece either converts a reader into a practitioner or loses them. These are the most impactful benchmarks for whether learning actually transfers.

Try This — Blocking
Blocking

Names a specific artifact or work product the reader would have at their desk this week — not "something you're working on" but a named thing: a prototype, a Figma file, a Jira backlog, a service flow diagram, a draft task statement.New

Test: remove "something you're working on" from the Try This. What remains? If the answer is nothing, rewrite with a named artifact. If the answer is a specific artifact, the benchmark passes.

Blocking

Achievable in one sitting, without setup, tool access, or coordination with people not already available. The time estimate or scope signal is present.

Blocking

Tests the piece's actual concept. The Try This is not a related activity — it exercises the specific mechanism the Concept section named.

Blocking

Trigger isolation test passes: the Trigger section reads as describing the reader's current week in complete isolation, with no additional context from elsewhere in the piece.New

Test: paste only the Trigger into a blank document. Does it immediately make sense to someone who hasn't read the rest of the piece? If it requires setup from the Concept to make sense, it's not a trigger — it's a conditional.

Proof — Blocking
Blocking

Proof appears after Try This. A Proof that precedes Try This is a preview — it tells the reader what success looks like before they've tried anything. The deliberate-practice loop requires attempt before feedback.

Blocking

States an observable external signal, not a self-assessment. "If six out of ten people couldn't find it" is observable. "If it felt like it worked" is not.New

Blocking

Two-state: addresses both outcomes. What does success look like? What does failure look like, and what does the reader do next in each case?New

A Proof that only validates success leaves the reader stranded when it doesn't work. Both branches should route the reader — success toward Take This Further, failure toward diagnosis or revision.

Take This Further — Blocking
Blocking

Reflection prompt matches learning type. Application → "what would you do differently?" Schema-update → "what didn't fit?" Synthesis → "what would you tell someone doing this for the first time?"

Blocking

Timeframe is specific and realistic. "In the next two to five days" is specific. "Soon" or "next time you have a chance" are not.

Blocking

The extended practice is genuinely different from Try This. It does not ask the reader to simply repeat what they just did — it extends the scope, applies the principle to a new context, or requires the reflection component that Try This omitted.New

AI path — Blocking
Blocking

Framed post-attempt: "after you've run this yourself…" The AI path accelerates, never substitutes.

Blocking

Describes a specific AI task: names what to give the AI (the input) and what to ask for (the output). "Use AI to help" is not specific. "Upload your session notes and ask it to group problems by type" is.New

Advisory
Advisory

Try This + Take This Further form a credible spaced practice arc: one immediate, one 2–5 days later. Together they cover initial encoding and spaced retrieval — the minimum viable deliberate-practice structure.

Advisory

If a public share prompt is included in Take This Further, the channel is named. "If you share it" with no channel named is unactionable.

Advisory

AI path describes achievable current capability — what Claude, ChatGPT, or equivalent can do today, not speculative capability. If the AI task described requires a feature that doesn't exist yet, revise it.New

Dimension 6

Sourcing Integrity

Every source is a trust claim. The worst outcome isn't a missing citation — it's a fabricated one or a misrepresented finding that a reader follows into a bad decision.

Blocking
Blocking

Minimum source count met. T100: ≥ 3 real sources. T200: ≥ 3 real sources. T300: ≥ 4 real sources across all parts.

Blocking

No fabricated sources. Every author, year, and publication is verifiable — either via WebFetch or as a well-documented foundational work with unambiguous attribution.

Unverifiable sources must be removed, not assumed correct. A source that is approximately right (right author, wrong year; right journal, wrong paper) fails this benchmark.

Blocking

Claims accurately represent what the source found. No overstating, no paraphrasing that changes the finding's direction or magnitude. When in doubt, quote the original phrasing.

Blocking

APA inline citation format used throughout: name in the sentence + year in parentheses, or (Author, Year) when name isn't in the sentence. Full citation details in the Sources block at end.

Blocking

Sources woven into prose at the point of claim — not batched at the end of a paragraph. A source that appears three paragraphs after the claim it supports fails this benchmark.

Advisory
Advisory

Source placement test: remove any citation from its sentence. Does the sentence lose credibility without it? If not, move the citation to the sentence where it would be missed.New

Advisory

At least one source is domain-primary — original research, a foundational academic paper, or a first-person practitioner study — not a synthesis blog or summary article.

Advisory

Recency: for empirical behavioral claims, prefer sources within 20 years. Classic foundational works (Grice 1975, Sacks et al. 1974, etc.) are exempt. A 2005 finding about digital behavior may not transfer to 2026 tools.New

Dimension 7

Audience Fit

Functional/practitioner workers only — PMs, custom dev, non-custom dev. No design background assumed. No leadership content. No reference to mandates. These are hard disqualifiers.

Blocking
Blocking

A functional practitioner with no design background can read, understand, and act on this piece without looking anything up.

Blocking

No design-coded vocabulary without plain-language handling. Required translations: user research → "talking to users / finding out what people actually do." Ideation → "brainstorming / generating options." Pain points → "what's frustrating / what's slowing them down." Design thinking → never use. Human-centered design → never use. Design sprint → describe the process. How might we → "what if we… / what would it take to…"

Blocking

No leadership-only content. Anything that requires organizational authority to act on — budget decisions, org structure, headcount, process mandates — does not belong in this library.

Blocking

No reference to the AI-adoption mandate or its consequences. The content stays entirely silent on this — the mandate belongs to leadership through separate channels.

Blocking

No illustrative examples, anecdotes, or invented stories. Information is presented directly. Examples read as calling out real situations — they are a danger zone regardless of how generic they seem.

Advisory
Advisory

"Real to them" test: the reader should feel this was written for their specific situation, not for a hypothetical practitioner. "You're building something right now" lands. "Teams often face" doesn't.New

Advisory

Transfer validity: if the piece addresses SaaS or 3rd-party contexts, the method works without design authority over the interface. If it's genuinely constrained to greenfield, the Trigger names that constraint.

Advisory

The Try This is executable by a PM, custom dev, or non-custom dev — not just by someone with design tools or design authority. If it requires Figma, design access, or a design team relationship, revise it.

Dimension 8

System Coherence

Each piece is a node in a network. Broken routing, phantom prereqs, or vocabulary drift between pieces degrades the whole library — not just the piece that caused it.

Blocking
Blocking

Metadata header is accurate: tier, arc placement, and prereqs all match the piece's actual content and position in the library. Verify against the master outline.

Blocking

What Next routing points to real pieces that exist in the library. No phantom piece references — if a piece number appears in What Next, it must exist in the file system and the master outline.

This was caught in production: "123 — Task vs Goal" was referenced in routing when the real piece is "123 — What Usability Testing Is." Cross-reference every routing link before publishing.

Blocking

What Next conditions are genuine decision points based on what the reader just learned — not "if you want more, read X." Each branch should route based on a specific outcome the reader just experienced.New

Test: replace "if you want more" with "if you just discovered [specific thing]." If the substitution reveals something meaningful, rewrite. If nothing meaningful is revealed, the routing is real.

Blocking

Prereq cross-references are layout elements (a chip or callout in the publish doc, below the article header) — not embedded in prose. A parenthetical like "if you're arriving here without reading X first…" inside the article copy fails this benchmark.

Blocking

No duplication: this piece does not cover ground already fully covered by another piece without adding a new angle or advancing to a new tier. Overlap is a signal to cut content or merge pieces.

Advisory
Advisory

Cross-piece vocabulary consistency: if this piece and another piece both describe the same concept (assumptions, attachment, signal, artifact), they use consistent vocabulary. Drift between pieces makes the library feel uncoordinated.New

Advisory

JIT ordering: each piece's listed prereqs would genuinely unlock something in this piece — not just thematically related, but conceptually required. If a prereq could be removed from the list without affecting the reader's ability to act on this piece, it's not a genuine prereq.New

Dimension 9

Publication Readiness

The publish doc is not supplementary — it's the interface between the article and its readers. A missing publish doc, wrong naming convention, or absent image spec means the piece isn't ready to ship.

Blocking
Blocking

Publish doc exists at [number].publish.md — correct naming convention. Not [number]-[title]-publish.md, not [number].qa-report.md, not any other variant.

Blocking

Layout map includes all required rows: Prereq chip (piece numbers + titles), image spec (Gemini prompt), pull quote (text + position), callout content (amber block text), What Next routing (piece links + conditions), platform (Teams vs SharePoint).

Blocking

Pull quote present and passes the quotability test: under 30 words as a unit, self-contained without context, names something the reader has felt or experienced — not something the author wants to explain.New

Test: could this sentence be a social media post that makes someone want to read the article? If yes, it's quotable. If it requires context from the piece to make sense, it fails.

Blocking

Platform specified. "Teams" or "SharePoint" is named. The platform determines layout behavior and the embed format for images and callouts.

Advisory
Advisory

Image spec describes an image that illustrates the concept — not decorates it. The image should be explainable in terms of the concept: "this image shows [mechanism or moment]."New

Dual coding (Paivio) applies: the image and the prose are encoding the same concept through different channels. An image that decorates provides no second encoding. An image that illustrates the mechanism adds retention durability.

Advisory

Forwarding scenario is specific enough to copy-paste as a Teams message. It names a specific colleague role (not "someone") and a specific workflow moment (not "when working on something").New

Test: could a developer paste this forwarding scenario verbatim and have it make sense to a PM colleague? If it requires editing to be specific, rewrite it.

Evaluation Protocol

Recommended Pass Order

Run passes in this order. Earlier passes catch disqualifying problems before you invest time in prose-level work. Each pass is a distinct read-through — not a simultaneous checklist scan.

  1. 1
    Sourcing Integrity (D6) Verify every source before investing time in anything else. A fabricated source invalidates the piece's trust anchor regardless of how well-written it is. Use WebFetch on any source that isn't a well-documented foundational work.
  2. 2
    Structural Completeness (D2) Confirm all required elements are present in the correct order for the piece's tier. Use the element sequence as a checklist. If Proof precedes Try This, stop — structural problems cascade through everything else.
  3. 3
    Audience Fit (D7) Check for hard disqualifiers: design-coded vocabulary, leadership content, mandate references, illustrative examples. These are binary — present or absent. Any hit is blocking.
  4. 4
    System Coherence (D8) Verify the metadata header, confirm What Next routing links are real, check for phantom piece references. A broken link in What Next misdirects every reader who reaches it.
  5. 5
    Learning Outcome Validity (D1) Confirm goal verb matches tier. Confirm the piece teaches exactly one thing. Apply the Bloom's alignment check. This is a conceptual pass — read for intent, not prose.
  6. 6
    Action Section Quality (D5) Read Try This, Proof, Take This Further, and AI path as a unit. Apply every blocking benchmark in D5. This is the highest-leverage section for whether the piece produces practitioners or just informed readers.
  7. 7
    Voice & Register (D3) Scan for banned words and openers. Then read the whole piece as a first-time reader and assess: does it feel like a peer or a function? Warm or clinical? Second-person or impersonal?
  8. 8
    Sentence-Level Craft (D4) Read aloud. Apply the rhythm audit, em dash inventory, and cut test. This pass takes the longest. It requires sentence-by-sentence attention — don't skim. Stumbles in the read-aloud locate problems faster than visual inspection.
  9. 9
    Publication Readiness (D9) Confirm the publish doc exists at the correct path, all layout rows are present, the pull quote passes the quotability test, and the platform is named. Final gate before commit.
Blocking — Pass Threshold

All blocking benchmarks must pass. A single failing blocking benchmark holds the piece. There is no score — it's pass or fail per benchmark. Document which benchmarks failed and what the fix is before re-evaluating.

Advisory — Pass Threshold

≥ 85% of advisory benchmarks should pass (roughly 13 of 15). Any advisory benchmark that fails must have a documented reason — "not applicable to this piece type" is a valid reason. "Didn't notice" is not.

When Evaluation Uncovers a Gap

If evaluation reveals a systematic gap — a benchmark that every piece fails in the same way — update the benchmark spec and add a remediation pass for the backlog. Evaluation is also a feedback loop for the spec itself.

Evaluation Frequency

Full evaluation pass on every piece before initial publication. Abbreviated pass (D6 + D2 + D5 + D9) after any substantive revision. Full re-evaluation only required if the goal, method, or sourcing changes.
