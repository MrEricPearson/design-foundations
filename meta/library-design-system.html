02 — Typography

Type System

Georgia body resolves cleanly at Surface Pro's 267 PPI — high-DPI screens remove the historical objection to serifs on screen. System-ui headers: zero webfont dependency. Monospace for all metadata.

ResearchNNGroup (2023): at 220+ PPI, serif body type matches or exceeds sans-serif readability. Georgia is the right call for Surface users. Visible Language literature review: target 50–75 characters per line (66 ideal). SharePoint default renders 90–110 CPL — see Column Layout section for the fix.

03 — Column Layout & Line Length

Fixing Line Length in SharePoint

The single highest-impact layout fix. SharePoint's default single-column layout renders text at 90–110 CPL. Research target: 66 CPL. The fix: Flexible Sections (available mid-2025, no SPFx required).

ResearchBaymard Institute + Visible Language (2005): optimal line length is 50–75 CPL (66 ideal). At 90+ CPL, readers lose their place at line returns and fatigue increases. WCAG 1.4.8 recommends 80 CPL maximum. SharePoint's default single-column is a measurable readability problem.

Recommended Layout: Two-Column with Narrow Navigation

Content column — 680px Max-width constrains line length to ~66 CPL at 16px body All patterns (P1–P12) render inside this column
Navigation / ToC column Flexible width — fills remaining space Contents: piece number + title + section links (T300 only) Leave blank for T100/T200 unless arc has 5+ sections

How to configure in SharePoint Modern (no SPFx needed)

  • In SharePoint page edit mode: Add section → choose "Flexible section" (available mid-2025 in Microsoft 365)
  • Drag left column to approximately 70% width — right column fills remainder
  • Place all content web parts (Text, Image, Quick Links) in the left column
  • For T300 arcs: place a Quick Links web part in the right column listing arc parts
  • For T100/T200: leave right column empty or hide with a Spacer web part
  • If Flexible Sections are not yet available in your tenant: use a 2-column layout with the 2/3–1/3 option and place all content in the wider column
  • Fallback without custom layout: use a single-column layout and apply max-width via the Script Editor web part if the tenant permits it: body { max-width: 680px; }

04 — White Space System

Spacing Between Sections

White space isn't padding — it's comprehension. Wichita State University research found ~20% comprehension improvement from generous inter-paragraph and section spacing. SharePoint's default is tight. This must be corrected manually.

ResearchWichita State / eLearning replication: white space between paragraphs and around page margins increases comprehension ~20%, with a slight reduction in reading speed. Net effect is positive for learning content. Source: Cieden, Shift eLearning (citing primary research).

Place a Spacer web part between major pattern transitions. Minor transitions use SharePoint's natural paragraph spacing.

05 — Mobile & Touch

Surface Pro and SharePoint Mobile

Surface Pro operates as a touch device at 267 PPI. SharePoint Mobile renders pages in the SharePoint app (iOS/Android). Both require specific treatment for tap targets, font scaling, and color blocks.

  • Touch target minimum: 44×44px for all interactive elements (What Next chips, Check-In options). SharePoint Quick Links web part meets this by default — verify custom link styles do too.
  • Font size floor: Never below 14px body text in SharePoint mobile app rendering. Georgia 16px (desktop) renders as approximately 14px in the mobile view — acceptable. Do not reduce body type below 16px on desktop.
  • Color blocks on mobile: Concept Panel (P3), Try This (P6), and Watchout (P5) rely on tinted backgrounds. SharePoint mobile preserves these in the Text web part — test in mobile view after publishing. If a web part uses a Highlighted Content block instead of Text, test separately — rendering varies.
  • Left borders on mobile: Concept Panel and Watchout use left-border treatment. These render correctly in SharePoint mobile. If custom HTML was used instead of Text web part formatting, verify in mobile SharePoint before publishing.
  • Pull Quote (P11) on mobile: The top-border + italic style reads well at mobile widths. Do not add a left border for mobile — adds visual noise at narrow widths.
  • Two-column layout on mobile: SharePoint automatically stacks Flexible Sections to single-column on narrow viewports. The right navigation column disappears — acceptable. Confirm the right column contains no critical content, only navigation.
  • Check-In (P12) on mobile: Microsoft Forms and Quick Poll web parts are mobile-responsive by default. Verify embedded Forms render correctly in the SharePoint mobile app — not just a mobile browser.
  • Image blocks on mobile: Set images to "Full width" in the Image web part settings — this ensures they scale to viewport rather than overflowing.

Pattern 02

Section Block

Prior Knowledge

You've watched a requirement shift mid-sprint. You know the feeling — the work you scoped two weeks ago isn't quite what anyone is describing now, and nobody announced the change.

What's Actually Happening

Requirements drift when decisions are made in conversation and never written down. The verbal agreement is real. It just doesn't match the doc. The doc is what gets built.

SharePoint web part:Text
  • Two heading weights: Primary (Concept, Method, Try This, Watchout, Artifact) — 700, text-2. Secondary (Prior Knowledge Hook, Trigger, Take This Further, AI Path) — 600, text-3

Pattern 04

Step Sequence

How to Run It

  1. 1Pull up the requirements doc for something currently in progress.
  2. 2Read every sentence containing "the user will" or "the system will." Highlight each one.
  3. 3Write A or F in the margin beside each — assumption or fact. A fact has evidence. Everything else is an assumption.
  4. 4Count. If more than half are A, the doc has a drift risk.
SharePoint web part:Text — numbered list
  • Monospace step number in accent chip — system-ui step text at 16px
  • Each step is exactly one action — if a step contains "and," split it
  • Imperative verb opens every step — no "you should" or "consider"
  • No explanation inside the step — explain in Concept, not Method
  • Maximum 6 steps. More than 6 = re-scope the piece.
Pattern 05

Watchout Block

Watchout

The failure mode is tagging everything as an assumption to feel thorough. If you end a session with 40 assumptions and no path to test any of them, the list is a way to feel like you did the work without reducing risk. One testable assumption this week beats a list you'll never return to.

SharePoint web part:Text — HighlightedRust/red tint
  • Rust border + tint — one Watchout per piece, maximum
  • Names the failure mode first, directly — no softening
  • Personal register — "you" not "teams" or "practitioners"
  • Specific to THIS method's failure — not generic caution
  • Never ends with reassurance — states the honest thing and stops
Pattern 06

Try This Block

Try This — 5 minutes

Pull up one active requirements doc right now. Run the A/F scan on the first page only. Don't finish the whole doc — one page is enough to see the pattern.

SharePoint web part:Text — Highlighted or BannerAmber tint — most visually distinct block on the page
  • Amber border + tint — strongest visual signal on the page
  • Time estimate always in the label: "Try This — 5 minutes"
  • Names a specific artifact the reader already has — never generic
  • Achievable in the same sitting — zero setup, zero dependencies
  • Proof (P7) follows immediately — never before
  • Spacer (32px) before this block — largest breathing gap in the piece
Pattern 07

Proof Block

Try This — 5 minutes

Pull up one active requirements doc right now. Run the A/F scan on the first page only.

If It Worked

You'll find at least one statement you thought was a fact that's actually an assumption — and you'll know exactly who could confirm or disprove it.

SharePoint web part:Textwith Divider web part above (not Spacer)

  • One observable signal, one sentence

Pattern 11 — New

Pull Quote New

Research basisEye-tracking study of 26 readers across 34 newspaper pages: fixation on pull quotes happens before body text — they function as a second headline for scanner-first readers. Directly portable to SharePoint Text web parts. Source: ResearchGate (journalism eye-tracking, 2019).

What's Actually Happening

Requirements drift when decisions are made in conversation and never written down. The verbal agreement is real. It just doesn't match the doc. The doc is what gets built.

"The doc is what gets built — not the conversation."
SharePoint web part:Text — Quote styleor Highlighted Content
  • Bold top border (2px, text-1) + hairline bottom border (1px, border) — not a colored block
  • Georgia italic, 18px — larger than body, smaller than H1. Max 52ch.
  • The quotable line required by the writing spec — this is its visual home
  • Placement: immediately after the Concept Panel — surfaces the key insight for F-pattern scanners before they reach the Method
  • One per piece. Never more than one.

  • No attribution line — the piece itself is the source
  • Do not use for T100 pieces under 400 words — the quote will feel oversized relative to the content
Pattern 12 — New

Check-In New

Research basiseLearning industry research (multiple 2024 meta-analyses): interactive elements increase time-on-task by ~36% over static text. SharePoint's Quick Poll and Forms web parts can approximate this without SPFx. Secondary benefit: gives you completion data — did people actually do the exercise?

Quick check

Did you run the A/F scan?

Yes — here's what I found
Not yet — saving for later
This doesn't apply right now
SharePoint web part:Microsoft Forms (embedded)or Quick Poll web part
  • Placement: after Proof (P7), before Take This Further — the piece is done, this is the bridge to spaced practice
  • One question only — not a quiz, not a survey. One.
  • Question format: "Did you [verb from Try This]?" — mirrors the Try This action exactly
  • 3 response options: yes + finding | not yet | doesn't apply. No right/wrong.
  • Anonymous response is acceptable — the goal is engagement signal, not grading
  • Link the "yes" option to the Take This Further channel where that applies
  • Optional for T100 pieces — where Try This is observational and hard to confirm
  • Required for T200 and T300 pieces where Try This has a tangible output
  • SharePoint Forms web part must be tested in mobile SharePoint app separately from browser
  • Response data: review monthly — high "not yet" rates signal the Try This prompt needs to be more specific or lower-effort

Image Spec Format

Image Spec

Written during the companion publish doc phase. Self-contained brief for Gemini Imagen generation or a human illustrator. Every image in a piece gets a spec before production begins.

IMAGE-SPEC id: img-001 piece: 205-requirements-drift placement: after-concept (between Concept Panel and Pull Quote) purpose: Illustrate the gap between verbal agreement and written record dimensions: 1360x680px (display at 680x340 — 2x for Surface Pro retina) style: Flat illustration, no shadows, no people, no gradients, no 3D palette: Ground #F5F3EE, Accent #3B5A9A, Amber #E8A835, Text #1C1B18 alt-text: "Two panels. Left: a speech bubble labeled 'Agreed in standup' with a checkmark. Right: a document icon labeled 'Requirements doc' with a checkmark and a question mark beside it." gemini-prompt: "Flat vector illustration, warm off-white background (#F5F3EE). Two equal panels side by side, separated by a thin vertical line in (#D8D5CE). Left panel: a speech bubble shape in slate blue (#3B5A9A) containing a white checkmark, labeled below in dark text (#1C1B18) reading 'Agreed in standup.' Right panel: a document icon outline in (#1C1B18) with two list items — a checkmark in slate blue and beside it a question mark shape in amber (#E8A835) — labeled below 'Requirements doc.' Clean, minimal, no people, no drop shadows, no gradients. Professional, warm, slightly editorial. 1360x680 pixels, 2:1 aspect ratio."
  • Gemini prompt must specify: background hex, palette hex values, exact visual content, style constraints (no people, no shadows, flat, no gradients), and pixel dimensions
  • Alt text describes content fully — assume the image is invisible
  • If an image can't be spec'd to add clear value over prose — don't add the image
  • Gemini Imagen 3 handles this spec format well. If results are wrong: add "vector illustration style, like an editorial icon set" and retry.

Tenant capability tiers

  • Full CSS control available (Script Editor or SPFx): Use exact hex tokens. Implement column max-width constraint via CSS. Full fidelity.
  • Standard Microsoft 365 tenant, no custom code: Use Flexible Sections for column layout. Use built-in theme colors (blue for Concept, yellow for Try This, red for Watchout). Close approximation of full spec.
  • Restricted tenant (no custom web parts, no Script Editor): Use 2-column layout (2/3 + 1/3). Use Text web part Quote for Concept Panel, built-in highlighting for Try This and Watchout. Minimum viable fidelity — still effective.
  • Never use SharePoint's dark-background section presets for content — readability at length collapses. Reserve for decorative breaks only.
