### Body structure

**Opening (warmup moment — situational recognition):**  
Starts with the friction feeling: "every time you look at it, you see another screen they have to navigate." Sets up the recognition moment before naming the concept.

**Concept block (what + why it matters):**  
Introduces "no UI as a design goal" as interactions that genuinely work better without visual interfaces. Anchored with Weiser (1991) ubiquitous computing — technology that recedes into the background.

**You'll see it when (situation):**  
Names the contexts: hands-busy scenarios, voice-faster-than-navigation, agent-based automation of routine decisions. Examples: voice assistants, conversational AI, agent systems.

**The signal (checkable sign):**  
"You keep designing screens, and every screen feels like friction you're adding instead of clarity you're creating."

---

**Don't confuse this with (disambiguation):**  
Separates intentional no-UI design from cost-cutting/laziness. Uses Golden Krishna (2015) correctly — not "never build interfaces" but "stop assuming interface = answer."

Core distinction: remove UI and it works *better* = right call. Remove UI and people are guessing = more work, not less.

Reinforces with Nass & Reeves (1996) on conversational interfaces — people apply social rules. Works when interaction is genuinely conversational; fails when they needed glanceable info and you forced sequential Q&A.

---

**Try Noticing (observational practice):**  
Actionable prompt: pick something you're building or using. Walk through one task. Imagine no screen — talk to it, or it acts automatically, or agent handles it.

Calibration questions:  
- Does that feel faster, or like you lost control?  
- Faster + you trust it = candidate for no UI  
- Feels like gambling on understanding = screen wasn't the problem, interaction model was
